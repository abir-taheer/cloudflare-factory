# Blocking lint contract

Run `docker compose run --rm tools npm run lint`. `npm run check` runs lint before unit tests; CI runs lint before starting infrastructure or applications. Every lint checks Prettier formatting, file/directory conventions, every rule test, exact dependency versions, type-aware Oxlint, official React hooks/compiler rules, and a complete React Doctor scan. Use `docker compose run --rm tools npm run format` for canonical formatting. There is no changed-line baseline or advisory mode.

Oxlint enables all seven categories as errors with TypeScript checking, type-aware rules, zero warnings and unused-disable errors. Plugins: TypeScript, Unicorn, Oxc, import, Promise, React (including hooks), React performance, JSX accessibility, Node and JSDoc. Category enablement covers the installed catalog rather than only the default preset. [Exceptions](rule-exceptions.md) document every explicit disabled rule. Generated output and dependency trees are excluded; authored code has no formatting exemption.

## Additional boundary and readability enforcement

`canonical-contract-imports` keeps schema/Effect names inspectable and rejects Zod v3. `no-effect-schema` also catches namespace access, re-exports and dynamic imports; native import restrictions are retained in every override. `no-untyped-api-routes` requires OpenAPI registration in API route modules, including named path constants. `require-schema-derived-contracts` rejects handwritten data contracts paired with their same-named Zod schema; inferred/derived contracts and behavioral interfaces remain allowed. These syntax checks do not prove arbitrary shape equivalence or perform secret taint analysis.

Native curly-all, complexity 20, 100 meaningful lines per function, one class per file and named-function conventions remain blocking. Oxlint does not implement brace-style or max-statements-per-line natively: `native-style-lint-rules.mjs` loads their actual ESLint implementations into the supported Oxlint JS plugin API, enforcing multiline 1TBS and one statement per line. Prettier is the only formatter.

Promise rules retain native behavior through `factory/prefer-await-to-then` and `factory/prefer-await-to-callbacks`, with lexical import checks for real Effect APIs and direct Node promisify adapters. Shadowed names are not exempt. `factory/no-sync-node-io` replaces Node's suffix-only no-sync rule: real imported synchronous Node I/O is forbidden; pure Effect.runSync is not I/O.

React uses automatic JSX, .tsx/.jsx files, MUI's typed sx props, and blocking hooks/compiler diagnostics. Effects are checked for derived state and unsafe synchronization patterns rather than blanket-banned. The official hooks recommended preset is promoted entirely to errors. React Doctor's stock JSON must also indicate a complete scan; exit status alone is insufficient.

Behavioral snippets test rejection and neighboring valid patterns; configured CLI regressions verify actual enabled rules, including API schema extraction and review boundary bypasses. Tests execute on every lint.

References: [Oxlint catalog](https://oxc.rs/docs/guide/usage/linter/rules.html), [JS plugins](https://oxc.rs/docs/guide/usage/linter/js-plugins), [RuleTester](https://oxc.rs/docs/guide/usage/linter/writing-js-plugins), [official React hooks rules](https://react.dev/reference/eslint-plugin-react-hooks).

The separate official hooks gate uses `recommended-latest` (all severities promoted to error), plus `react-hooks/hooks`, `capitalized-calls`, `memo-dependencies`, `exhaustive-effect-dependencies`, `no-deriving-state-in-effects`, `syntax`, and `rule-suppression`, all errors. Root invokes its pinned ESLint 9 executable explicitly with `--no-inline-config`; Doctor's transitive ESLint version cannot silently replace this gate. Doctor runs all applicable rules with no cache or inline-disable respect and validates complete JSON before accepting success.

`factory/require-named-complex-conditions` requires named boolean decisions for inline array/object literals and chained call receivers in `if`, ternary and loop tests. Simple predicates, comparisons, named booleans and calls on existing collections remain allowed. Function bodies passed as callbacks are separate scopes. Native complexity, no-nested-ternary and max-nested-calls measure different constructs; the installed catalog has no equivalent targeted condition-extraction rule. There is no autofix: preserve short-circuit evaluation and recalculate loop predicates at the original frequency.

Rules and their tests are grouped under `api`, `effect`, `quality`, `security` and `testing`. The root lint command uses Node 24's quoted recursive `packages/lint-rules/tests/**/*.test.mjs` glob, including tests retained at the test root. Authored directories are limited to 20 direct files by the shared path gate; the lint package has no exemption.

The generated client is checked on every lint with `npm run check:generated --workspace @factory/api-client`. Only `packages/api-client/src/api-paths.d.ts` has the four generator-style exceptions listed in [the exception inventory](rule-exceptions.md#generated-api-declaration); all other authored files remain strict, and declaration type/security checks remain active. OpenAPI output and declaration text must exactly match fresh, formatted generation.
